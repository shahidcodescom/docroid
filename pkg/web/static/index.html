GETTING STARTED

Quickstart & Installation

Docroid is written in pure Go with zero external runtime dependencies. It runs completely non-rooted inside Android Termux or standard Linux environments.

Zero-Daemon Guarantee: Unlike Docker which runs a persistent 300MB daemon in the background consuming battery, Docroid processes run natively or via lightweight sandboxes. When apps are stopped, 0% CPU and 0MB memory are consumed.

Installation on Termux (Android)

BASH (TERMUX) 
# 1. Download precompiled static binary
curl -L -o $PREFIX/bin/docroid https://raw.githubusercontent.com/runerail/docroid/main/bin/docroid
chmod +x $PREFIX/bin/docroid

# 2. Verify environment with System Doctor
docroid doctor

# 3. Launch Web UI Dashboard
docroid ui -p 9190

Deploy Your First Containerized App

TERMINAL 
# Launch background web server with port mapping
docroid run -d -n web-demo -p 8080:8080 python3 -m http.server 8080

# Check running processes
docroid ps

# View real-time logs
docroid logs web-demo -f

# Stop and remove container
docroid stop web-demo
docroid rm web-demo
INTERNALS

Architecture & Execution Engines

Standard Docker fails on mobile due to lack of kernel cgroups v2, missing overlayfs, and non-root limitations. Docroid bypasses these constraints using a dual-engine architecture:

NATIVE FAST-PATH

Native Fast-Path Engine

  • 0% CPU Loss: Executes Go binaries, static binaries, Node.js, and Python directly on Android kernel.
  • Workspace Sandboxing: Each app receives an isolated directory in ~/.docroid/workspaces/<id>.
  • PGID Process Groups: Clean process hierarchy management prevents orphan zombie processes.
ROOTFS SANDBOX

Rootfs Sandbox (PRoot / Alpine)

  • Standard Linux FHS: Provides full /bin/sh, /etc, /lib, and package managers (apk).
  • Micro-Footprint: Utilizes an ultra-lean ~3.2MB Alpine micro-rootfs.
  • Fake Root (UID 0): Virtualizes root privileges without modifying the device system partition.
RUNNING IN ROOTFS SANDBOX 
docroid run -d --rootfs alpine -n alpine-worker /bin/sh -c "while true; do date; sleep 5; done"

HOSTING

Static Website Hosting

Deploy production-ready static websites, Single Page Applications (React, Vue, Vite, Next.js exports), and documentation directly from your phone.

Features:

  • Virtual Host Multiplexing: Serve dozens of sites over standard HTTP port 80/8080 routed via the HTTP Host: header.
  • Dedicated Port Binding: Assign dedicated local ports for direct IP access (e.g. http://192.168.1.100:9091).
  • SPA Routing Fallback: Automatically serves index.html for non-file paths to support client-side routing.
  • Drag-and-Drop ZIP Upload: Instant extraction and deployment in the Web UI.
CLI STATIC SITE DEPLOYMENT 
# Deploy a directory with custom domain and port
docroid sites deploy --name my-portfolio --dir ./dist --domain myapp.local --port 9091

# List hosted static sites
docroid sites ls
DISTRIBUTED MESH

Kubernetes-like Cluster & Pods

Interconnect multiple Android devices, Raspberry Pis, and laptops into a distributed computing mesh with zero cloud dependencies.

Clustering Capabilities:

  • Distributed Raft / Gossip Discovery: Autonomous peer interconnect over local Wi-Fi or hotspot.
  • Replica Scheduling: Automatically balances Pod replicas across available connected nodes.
  • Real-Time Live Scaling: Dynamically increase or decrease replica count on the fly from the Web UI or CLI.
  • Zero-Downtime Rolling Updates: Updates pods incrementally while maintaining service availability.
INITIALIZE & SCALE CLUSTER 
# Device 1 (Master / Control Plane):
docroid cluster init --listen :9100

# Device 2 (Worker Node - Phone B):
docroid cluster join 192.168.1.50:9100 --token <cluster-token>

# Deploy a multi-replica service across nodes:
docroid cluster deploy --name api-service --replicas 4 --image python3 -p 8080:8080

# Scale replicas dynamically:
docroid cluster scale api-service --replicas 8
NETWORKING

Virtual Networking & Inter-Container Intercom

Docroid enables microservices and multi-container apps to communicate using service names and aliases without root privileges.

Zero-Root Resolution Mechanism: PRoot rootfs sandboxes receive an isolated dynamic /etc/hosts mapping container names to 127.0.0.1. Simultaneously, Docker link environment variables (e.g. API_HOST, DB_PORT) are injected into native and rootfs processes.
INTER-CONTAINER COMMUNICATION WORKFLOW 
# 1. Create a virtual bridge network
docroid network create microservices

# 2. Run backend API attached to the network with alias
docroid run -d -n backend --network microservices --network-alias api -p 9299:9299 python3 -m http.server 9299

# 3. Run frontend client communicating directly via 'api:9299'
docroid run -n frontend --network microservices python3 -c "import urllib.request; print(urllib.request.urlopen('http://api:9299').status)"
ORCHESTRATION

Compose Stacks

Define multi-container environments declaratively using standard docroid-compose.yml or docker-compose.yml formats.

SAMPLE DOCROID-COMPOSE.YML 
version: "3.8"
services:
  web:
    image: native
    command: python3 -m http.server 8080
    ports:
      - "8080:8080"
    networks:
      - internal
    depends_on:
      - db
  db:
    image: rootfs:alpine
    command: sqlite3 /data/app.db
    volumes:
      - "./data:/data"
    networks:
      - internal

networks:
  internal:
    driver: bridge

MOBILE TUNING

Android, Termux & Battery Optimization

Android OS aggressively kills background processes to save battery. Follow these production best practices to ensure continuous 24/7 container operation:

  • Acquire Wake Lock: Run termux-wake-lock in Termux to keep CPU alive when device screen is turned off.
  • Disable Battery Optimization: In Android Settings → Apps → Termux → Battery → Select Unrestricted.
  • Disable Phantom Process Killer (Android 12+): Android 12 introduced a 32-process limit. Disable it via ADB if running large clusters: 
    adb shell "/system/bin/device_config put activity_manager max_phantom_processes 2147483647"

Frequently Asked Questions

Q: Can I run Docker Hub images?

Yes, rootfs containers can unpack and run root filesystems extracted from Alpine, Ubuntu, or custom container images using PRoot.

Q: Does Docroid require root?

No. 100% of Docroid features (networking, apps, static hosting, clustering) are designed to run non-rooted.
